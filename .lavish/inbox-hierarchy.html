Implemented behavior

  1. Group by actual parent IDs within the workspace. Include only matching inbox notifications plus the ancestors needed to explain them; do not load every sibling task.
  2. Keep parent notifications selectable and independently actionable. A context-only parent opens its issue without creating a notification or marking children read.
  3. Sort each group by its latest matching notification; sort sibling branches the same way. Parent stays first. Counts describe inbox items, not all subtasks.
  4. Unread, status, actor, and priority filters match notifications first. Restore necessary ancestors as context. Do not change a child’s read state when expanding or opening its parent.
  5. Archive remains per issue. An archived parent can remain as context for an active child; archived notifications stay in the archive view.
  6. Support deeper ancestry, cap visual indentation at two steps, and expose the full path in the detail pane. Deleted or inaccessible ancestors leave their children visible without leaking parent data.

Implementation notes

  1. Enrich active and archived inbox responses with authorized ancestor references in batches. Keep this additive and optional in the schema so older backends still render a flat list.
  2. Build a pure hierarchy projection in core after deduplication and filtering. Use stable issue/workspace keys, cycle protection, and explicit context rows.
  3. Render a flattened set of visible rows through the existing virtualizer. Store only collapsed IDs as view state. Use real disclosure buttons with aria-expanded; preserve row focus and selection.
  4. Use the visible order for arrows and post-archive selection. Reveal ancestors for a selected deep link. Refresh hierarchy on reparenting and deletion events.
  5. Test missing/filtered/archived parents, multi-level trees, unread counts, ordering, cycles, reparenting, deep links, and collapse keyboard behavior. Cover schema drift and authorization in API tests.
