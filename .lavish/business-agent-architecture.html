01 · How the moving parts connect

Use ports and adapters: the core calls typed interfaces, while provider integrations and vertical modules implement them. Workflow code decides the sequence; agents interpret ambiguous input and propose actions within that sequence.

Inputs

Phone calls · SMS · WhatsApp · Email · Web chat
Also accept internal events, scheduled reminders, and operator requests.

↓ authenticate provider, resolve tenant, capture original content
Channel adapters

Verify webhooks, deduplicate provider events, normalize text and attachments, record channel capabilities. Preserve provider IDs and delivery metadata.

↓ durable inbox event + attachment references
Identity & case routing

Resolve contact identities and conversation threads. Attach the event to an existing case or open one. Escalate ambiguous identity or case matches.

↓ tenant-scoped case snapshot + evidence
Operations core

Workflow coordinator → context assembly → agent or deterministic step → action proposal
Loads the vertical’s workflow, schemas, knowledge rules, and permitted capabilities. Persists steps, waits, deadlines, and human ownership.

↓ validated proposal + evidence + expected record version
Policy & action gateway

Check permissions, business invariants, freshness, communication eligibility, and tenant policy. Approve automatically where allowed or create a human review task.

↓ authorized, immutable action revision
Execution adapters

Update internal records · call CRM, calendar, carrier, or dealer systems · generate PDF artifacts · send email or messages. Record receipts and reconcile uncertain outcomes.

↺ delivery receipts, external events, replies, and timeouts become new workflow events
Across every layer: tenant isolation, audit trail, trace IDs, cost budgets, secrets, retention, and operator visibility. The same execution gateway applies to agent, workflow, and operator commands that create business side effects.

Live calls need a separate fast path

A voice session handles streaming speech, interruptions, transfer, and short tool calls. It shares the case and action gateway. Slow document processing and approvals continue asynchronously; the caller can receive a later update.

Store transcript turns and final call events with stable IDs. Interim transcription is provisional evidence. A finalized transcript must not create duplicate actions already initiated during the call.

The operator console closes the loop

Share a timeline, review queue, action preview, evidence viewer, retry controls, and usage panels. Vertical screens add claim details, booking calendars, or vehicle inventory.

A human takeover pauses automation for that case. Resume explicitly after new facts and pending proposals have been reconciled.

A vertical module contains executable code as well as configuration. Pricing, availability, and record validation belong in typed domain functions. Tenant settings choose supported behavior; they cannot bypass platform permissions or domain constraints. Use namespaced capabilities instead of a universal “update any record” tool.

Keep facts and knowledge distinct

Read current balances, availability, policy versions, and booking status through authoritative data adapters. Search documents for explanations and supporting passages, with tenant and access filters applied before retrieval.

Each extracted fact carries source, timestamp, and validation status. Each document citation includes its version and location. Conflicting or expired evidence becomes a review task.

Give agents bounded responsibilities

Classify intent, extract facts, summarize, and draft. Domain functions compute prices, check eligibility, and enforce constraints. Models receive only the capabilities allowed for the current step.

Version prompts and output schemas; validate results before use. A confidence score alone never authorizes a consequential action. Treat incoming text and documents as untrusted data.

04 · Small contracts, explicit ownership

The case is the coordination record. A conversation is a channel thread; one case can span several conversations, and a conversation can discuss several cases through explicit links. Do not force every domain object into the case table.

Capability contract

Every write capability declares an input/output schema, required permission, side-effect class, validation/precondition function, execution handler, and reconciliation handler. Add compensation only when the business operation supports it.

A module supplies venue.placeHold; a calendar adapter implements its external sync. The shared gateway owns authorization and receipts.

Storage ownership

Postgres stores case state, workflow metadata, actions, approvals, audit events, and transactional inbox/outbox records. Each vertical owns its domain tables and migrations.

Object storage holds original MIME, recordings, attachments, and rendered PDFs. Search indexes and summaries are derived views. Preserve audit metadata while allowing content removal under tenant retention policy.

External systems need an ownership map. Declare the source of truth per entity or field. For example, the platform can own a venue hold while a calendar is its projection; a carrier may own claim status. Synchronization tracks external versions and correlation IDs, suppresses echoed writes, and surfaces conflicts instead of overwriting silently.

05 · Deploy simply, scale at the pressure points

Both repositories already use Hono, Cloudflare Workers, Prisma, and React. Preserve that investment. Start with one modular backend per product, shared versioned packages, and separate environments. A shared codebase does not require one shared production database.

Recommended starting shape

Cloudflare runtime adapters

  • Workers: authenticated APIs, webhook ingress, provider adapters.
  • Queues: buffer ingestion and execution. Delivery is at least once, so consumers must tolerate duplicates. Official guarantee.
  • Workflows: durable steps, retries, timers, and waiting for approvals or external events. Official capabilities.
  • Durable Objects: use where a case or live session needs coordinated access; retain database revision checks at writes. Official overview.
  • Postgres + object storage: retain existing data adapters; avoid an ORM or database migration just to share code.

Reliability is an application contract

  1. Persist inbound event and outbox entry together. Acknowledge only after durable acceptance. Upload blobs first; clean orphaned uploads later.
  2. Publish outbox entries with retry; deduplicate again at the consumer. Order case processing by persisted revision, not queue arrival.
  3. Commit domain writes and local audit/outbox records atomically. External calls use stable action keys and execution receipts.
  4. On timeout, reconcile using provider status or a read-back. If the provider cannot prove the result, hold for operator review.
  5. Verify the business postcondition before reporting success. Retry notification separately from an already completed business write.

Protect each tenant

Scope database, retrieval, storage, caches, and jobs. Resolve webhook tenants from verified channel bindings and operator tenants from authenticated membership. Keep credentials outside model context.

Bound the workload

Use per-tenant admission budgets, concurrency limits, provider rate limits, retry backoff, and dead-letter queues. Split voice, extraction, and outbound workers when their latency or resource needs diverge.

Measure business outcomes

Track cost per resolved case, queue age, approval wait, time to useful reply, delivery failures, unknown writes, and human corrections. Trace event → run → proposal → execution → receipt.

Autonomy rollout: shadow proposals with no egress → human-approved execution → automatic execution for selected action classes. Promote per tenant and capability using evaluated evidence. A kill switch blocks new external effects and sends pending work to humans; it does not erase the audit trail.

06 · Build from two real workflows

Use milestones with exit criteria. Estimates depend on current production traffic, connector readiness, and team capacity, none of which were verified in this review.

1 · Establish baselines

Pick one narrow slice in each product

Insurance: inbound email → extract missing claim details → approved request for documents. Venue: inbound email → extract event details → approved request for missing information. Record current behavior with sanitized fixtures, including failures and human edits.

Exit: repeatable fixtures, source ownership documented, and baseline correctness, latency, and cost measured.

2 · Extract the kernel

Share contracts and the proposal lifecycle

Create a platform package workspace consumed at pinned versions by both apps. Extract tenant context types, event/evidence contracts, agent result validation, action policy interfaces, and execution receipts. Keep each app’s database adapter in place.

Exit: both products exercise the same contract suite; no insurance or venue nouns in the shared kernel.

3 · Complete both slices

Run real workflows through the same interfaces

Implement the module registry, email adapter, workflow adapter, and review view. Migrate a selected case cohort to the new path. Shadow replay uses a sink adapter so it cannot send messages or mutate external records.

Exit: duplicate delivery, crash recovery, expired approval, cross-tenant access, and provider timeout tests pass in both products.

4 · Add harder capabilities

Bring in domain writes, messaging, and documents

Register insurance triage and venue hold/quote capabilities. Add WhatsApp/SMS adapters and PDF rendering when a workflow needs them. Enforce channel eligibility at send time. Introduce voice as its own streaming adapter after asynchronous execution is reliable.

Exit: end-to-end sandbox runs show correct records and delivery receipts; domain invariants still have deterministic tests.

5 · Prove a third vertical

Use a dealership pilot as the abstraction test

Add inventory lookup and visit scheduling through a dealer module plus a dealer-system adapter. New workflow code should compose existing core primitives. If each new vertical requires core branching, revisit the interface before adding more configuration.

Exit: a new vertical ships without changes to core routing, approval, or execution semantics. Measure actual onboarding effort.

Suggested package seams

@business/contracts · pure schemas and identifiers
@business/runtime · cases, workflows, actions, policy ports
@business/cloudflare · runtime implementations
@business/channels · provider adapters
@business/console · headless hooks and shared review views

Keep insurance and venue modules in their product repositories initially. Add a shared package only when it has a real owner and two consumers.

Cutover and rollback

Pin package, workflow, prompt, schema, and module versions. Route each case to one execution owner. Let old in-flight runs finish on their pinned path; migrate them only with an explicit state mapper.

Roll back routing for new work, pause affected execution, and reconcile outstanding sends. Preserve action keys and receipts across versions so rollback cannot duplicate completed effects. Prefer additive storage changes during adoption.

SeguroHQ · insurance-site

Start with its action gateway

The current proposal function validates through a registered adapter, deduplicates by organization and idempotency key, atomically records the proposal and event, and applies approval policy. Execution distinguishes local record changes from queued outbound actions.

Extraction candidate: lifecycle and policy interfaces. Leave claim-specific payload validation in the insurance module. Older implementation notes describe fewer supported action kinds than the current source.

Encore · venue-site

Borrow its pipeline boundaries

The conversation pipeline grounds extracted facts, calls availability and pricing separately, composes a reply, and persists an agent contract. Approval workflows and idempotent message ingestion are present. Price and date calculations have dedicated deterministic functions.

Extraction candidate: run/evidence contracts and workflow ports. Keep pricing, capacity, opening hours, and booking constraints local.
