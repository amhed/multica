# Reaper UX trigger — implementation notes

## Task 9: HostRow action, dialog, i18n

- `resolveHostReap`/`hostReapKeys` (Task 8, `packages/core/agents/host-reap.ts`) were not re-exported from `packages/core/agents/index.ts`. Added `export * from "./host-reap";` there so views can import from `@multica/core/agents` like every other agents query/mutation, instead of reaching into a bare relative path.
- Role gating lives in `HealthCard`, not per-`HostRow`: one `memberListOptions(wsId)` query computes `canManageWorkspace` once and passes it down as a prop, rather than each row re-deriving it. `wsId` is already a required prop on `HealthCard`, so this skips the `useCurrentWorkspace()` step from the workspace-tab pattern (that hook exists to derive `wsId` from the route, which isn't needed here).
- `ReapDialog` is always "open" while mounted (`<Dialog open>`); the parent (`HostRow`) conditionally mounts/unmounts it. `onClose` is the only way out — used for cancel, backdrop/escape dismissal (blocked while `phase === "applying"`), and after both a successful and a failed apply (the result surfaces as a toast, not inline, since the dialog is gone by then).
- Apply failure (`status !== "completed"` or `result == null`) is treated as one case: toast an error and close. The brief calls out `failed`/`timeout` as distinct from `completed`, but for the *apply* step specifically there's no useful state to keep the dialog open for — the fresh re-selected list is already stale, so we don't try to redisplay it. Preview failure/timeout keeps its own dedicated dialog state (`"unavailable"`) with retry, since staying on the dialog to retry the scan is exactly what's actionable there.
- Added an `age_value` i18n key (`"{{seconds}}s"` in EN) instead of concatenating `{process.age_seconds}s` in JSX — the trailing literal `s` tripped `i18next/no-literal-string`, and it's also locale-dependent (JA/KO use different unit markers).
- Locale parity: the plan only called out `zh-Hans`, but `packages/views/locales/parity.test.ts` requires every registered locale (fr/ja/ko/zh-Hans) to cover every EN key. Added the `reap` block to all four. `zh-Hans`/`ja`/`ko` have no CLDR "one" plural category (checked via `Intl.PluralRules(locale).resolvedOptions().pluralCategories`), so their `count` key only has `_other`; `fr` has "one" and needed both `count_one`/`count_other`.
- Fixing the role-gating addition broke two adjacent test files that don't mock `@multica/core/auth` (`active-board-page.test.tsx`) or now need two distinct `useQuery` mocks keyed by query key (`host-health-card.test.tsx`, rewritten to route by `queryKey`). Updated both rather than leaving them red.
